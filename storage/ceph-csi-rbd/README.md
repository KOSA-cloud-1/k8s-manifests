# Ceph CSI RBD

The workloads use the `ceph-rbd` StorageClass for database PVCs. Object
storage continues to use Ceph RGW through S3 credentials in `ceph-secret`.

Storage inputs:

- Ceph cluster ID: `861f6095-c334-413a-95a0-04e197f430c2`
- RBD pool: `rbd-team1`
- Ceph auth entity: `client.TEAM1`
- Kubernetes CSI Secret `userID`: `TEAM1`
- Reclaim policy: `Retain`
- RBD encryption: disabled

Install the RBD CSI driver before applying `00-storageclass.yaml`.

```bash
helm repo add ceph-csi https://ceph.github.io/csi-charts
helm repo update

helm upgrade --install ceph-csi-rbd ceph-csi/ceph-csi-rbd \
  --namespace ceph-csi-rbd \
  --create-namespace \
  --version 3.16.2 \
  -f ceph-csi-rbd-values.yaml
```

The current cluster uses a single known Ceph monitor endpoint:

```yaml
csiConfig:
  - clusterID: 861f6095-c334-413a-95a0-04e197f430c2
    monitors:
      - 10.10.10.11:6789
```

Additional monitors can be appended later if Ceph admin provides the full
`mon_host` list.

The `ceph-csi-rbd-secret` is generated by External Secrets Operator from
AWS Secrets Manager key `prod/ceph-rbd` property `userKey`.

Validate provisioning:

```bash
kubectl apply -f namespaces/00-namespaces.yaml
kubectl apply -f external-secrets/
kubectl -n ceph-csi-rbd wait externalsecret/ceph-csi-rbd-secret \
  --for=condition=Ready --timeout=120s
kubectl apply -f storage/ceph-csi-rbd/00-storageclass.yaml
kubectl apply -f storage/ceph-csi-rbd/10-test-pvc.yaml
kubectl -n data get pvc ceph-rbd-smoke-test
```
